# Does the Lean ePBS model agree with the Gloas reference?

The reference is consensus-specs v1.7.0-beta.4 at `aa16bb4c`. The audit starts with all 12,002 published Gloas reference cases. The 9,344 serialization cases test binary encoding and tree roots. The 1,472 additional fork-choice compliance cases have their own inventory. Per-case evidence, including which fixtures reached a payment branch, is in `payment-results.json`.

**What the source review checked.** For parent settlement we followed the empty-parent guard, request-root and count guards, epoch selection, positive-amount append and entry clearing before nested requests. For bids we followed both obligation queues, the minimum balance check, the current-half index and zero-bid handling. For votes we followed the historical roots, source/target/head conditions, bit updates, previous/current payment bank and first-participation guard. The compiled runner shares the proof's arithmetic and settlement definitions. Full-state equality includes fields updated by the surrounding Python operations.

**Other findings on the page.** The 72 fork fixtures check the pinned fork-slot availability bit, builder deposit routing, resulting builder balances and the retained deposit queue. Six fixtures include existing-builder top-ups. The 56 normal builder-deposit cases exercise a separate credential-first transition. The long-gap ring observation has a model witness; a serialization vector cannot exercise it. The report screens 281 multi-block fixtures and distinguishes operations in valid blocks from operations in a final rejected block. It gives them no full-chain conformance credit.

**What changed.** The runner now reads complete operation fixtures instead of treating synthetic theorem inputs as official evidence. We extracted the existing bid-entry construction and delayed-parent append into shared Lean definitions so the proofs and runner call the same functions. The pinned protocol rules and theorem statements stayed the same. Validity, projected fields, serialization and whole-state comparisons are recorded separately.

**Reproduction.** Use the single command and pinned setup in [the vector runner guide](../tests/reference_vectors/README.md). The CI workflow publishes the case IDs, input digests, spec and proof revisions, branch outcomes and supplemental checks.

**Suggested public wording.** Against consensus-specs v1.7.0-beta.4, our Lean payment logic agreed with the official vectors on the ePBS branches exercised; 109 accepted parent-payload, bid and ordinary-attestation cases also matched the complete expected state with surrounding consensus logic supplied by Python.
